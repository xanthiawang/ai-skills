# 游戏出海支付合作

先区分用户要解释机制、比较新旧协议，还是修改当前稿。具体合同/法律分析先读 [共同审查约束](../game-commercial-legal/references/core-review.md)；核验法源时可读 [资料入口](../game-commercial-legal/references/source-entrypoints.md)。依赖缺失时仅交付不依赖它的说明和材料缺口，不假装完成核验。

## 还原本次交易

从材料识别游戏/产品、地区、币种、签约主体、玩家销售方、发行/运营方、支付服务方、实际收款/结算方、开票方、退款及客服方。角色未知就留空。

分别追踪玩家订单、支付处理、余额/备付/保证金、商户结算、退款/拒付、费用/返利和数据。公司名称、账户名和收款路径不能单独证明代理、转售、MoR、持牌资格、税务或会计主代理关系。

## 按触发事实检查，不机械加条款

| 模块 | 核对的问题与材料 |
|---|---|
| 文件与产品 | 服务到底覆盖哪个主体、地区、游戏、支付方式？主协议、订单、费率表、平台规则、数据附件哪个优先？旧协议继续有效还是只对特定主体被替代？ |
| 关联方加入 | 加入的是独立订约方、受益人、共同义务人还是代付款方？谁负责账单、债务和数据？不能仅凭 joinder/affiliate 用词断言法律效果。 |
| 费用 | 百分比基数、固定费用、币种、兑换点/汇率来源、税费、最低承诺、优惠条件、调价通知/退出安排是否明确？不要套默认费率。 |
| 结算 | 何时产生结算权、何时到账、时区和工作日如何定义，是否需账单/发票/核对？“每月对账”不等于“对账当日付款”。 |
| 资金控制 | 准备金/保证金/留置/抵销/自动扣款的触发、范围、期限、通知、证明与释放机制是什么？终止后尾部责任如何清算？ |
| 退款与拒付 | 欺诈、未授权交易、友好欺诈、重复扣费、未交付分别谁负担？证据、争议期限、退款权限与额外费用是否可实际执行？ |
| 对账差异 | 报告字段和交易ID能否对应订单、到账、费用、退款、拒付、余额和保证金变化？差异如何提出、复核和纠正？ |
| 中断与退出 | 风控暂停、资金冻结、网络规则变化或监管要求如何处理？终止时未结款、未决拒付、用户服务、存量数据怎么办？ |
| 责任 | 玩家交付、支付执行、平台技术故障、第三方网络、赔偿、责任上限与例外如何切分？不默认某种限责在所有法域无效。 |
| 财税与合规 | 销售/服务所在地、交易主体、消费者、销售税/预扣税/汇款、牌照或制裁问题是否被触发？列给合适人员核验，不自填税率或承诺资质。 |
| 数据与安全 | 实际采集/交换什么数据、谁为谁处理、谁可决定用途、分包与跨境安排如何？不因双方说“不用DPA”就跳过数据角色判断，也不一概要求签同一份DPA。 |

## 输出与计算

先用普通中文解释合作链路，再按本轮需要给“条款/证据—问题—实际后果—最小修订—确认责任方”。分清业务、财税、数据和当地法律问题；已获材料确认与尚待确认分别标注。

需要算费率/到账/差额时，只用真实文件，保留原始币种、期间、精度和取数位置；检查费用、税费与退款是否重复扣减。资料不足则给符号结构和缺口，不造交易数据，不将测算当会计或税务定论。

不索取支付密码、完整卡认证信息或私钥。不执行收款、付款、退款、拒付提交、商户开户或配置变更。合同修改复用已有文档/合同技能，并落实共同约束中的副本与交付后检查。
