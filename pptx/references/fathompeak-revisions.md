# 沐仞 / FathomPeak PPT 修改规则

适用于 Zixin 的沐仞公司介绍、产品、品牌、营销及竞品比较 PPT。
来自已确认的修改偏好；用户当前指令优先。不要把这些偏好强加给其他项目。

## 原稿与版本

- 在用户指定的原 PPT 基础上局部修改，保留未要求变动的内容、顺序和视觉体系。
- 修改前核对实际文件、修改时间、页序和目标页；此前的插入记录、旧截图和交付记录不能代替当前文件检查。
- 保留可恢复的原版。用户要求更新原文件时，在备份后更新；若原文件被占用或可能存在未保存编辑，保存明确命名的修订版，说明应打开哪份文件。
- 交付完整 PPT，不以单独的图片、PDF、预览或代码代替。避免连续产生含义不明的“最终版”。

## 选定设计与高亮

- 沿用原稿及用户最终选定的字体、色卡和 UI 方案。选定一种方案后，删除用户要求淘汰的其他方案及其配套说明，不继续混用。
- 本项目默认标出新增和改写处；若用户要求干净版则不加高亮。文字用可读的浅色高亮；新增整页可高亮标题，图片本身保持原样。
- 参考 Dia、Every 等案例前，辨认用户要借鉴的是文字排版、插画、图片嵌入、线框、透明度或动态效果；不要把某项参考误解为全面更换视觉体系。
- 不以通用技能的铁锈色、Calibri、固定字号或“每页必须配图”等默认值覆盖现有品牌规范。
- 图的面积应与信息量匹配。密集图表保留完整总览；必要时在页数允许时增加局部放大，不能靠缩小文字硬塞。动画若被要求，应解释业务过程。

## 内容、分类与证据

- 表格保持用户给定的表头、行分类和对比逻辑。要求补充收费方式、获客渠道时，在原框架补充；国内与海外分开列。
- 同一分类列使用同一维度。“交付类型”按服务或产品划分；高校是客户类型，其采购、账号、配额等要求放入对应业务的附加要求。
- 交付物写到可交付的对象，验收写清测试内容、方法和凭证。不要仅用“技术支持”或“以合同为准”代替具体内容。
- 未确认的价格、性能阈值、负责人、日期、预算、执行进度和验收结果留空；必要时在表注说明待确认，不推测补齐。
- 确认没有的项目按用户要求写“无”；未核实不等于无。保留资料范围和证据不足的区别。
- 竞品价格注明币种、计费单位、模型或设备版本、日期及适用条件。区分公司宣传、实际功能、历史记录和已验证结果。
- “兼容 OpenAI / Anthropic 接口”“支持 Claude Code”不能直接改写为“销售 GPT / Claude 模型”。具体型号示例也不能替代当前可售性、价格及开通条件的核验。
- 网站设计说明逐项对应当前采用的网页：字体、色值、导航、页面架构、按钮、用户流程和实际状态。不得凭旧版截图或印象补写；本地原型与线上版本有差异时明确依据。

## 图片插入与最终验收

- “把这张图加到 slide”意味着找到正确原图或高清资产，真正嵌入目标 PPT，不能只另外附上图文件。
- 图片保留比例、完整标签及来源。不要用文件列表截图替代图表，不为统一风格擅自重画已有数据图，不把放大低清截图称为找到了高清原图。
- 不更改原图中的数据或事件，除非用户明确要求并有依据。保持可编辑标题、表格和其他原有对象；图片要求本身不必被改造成可编辑图表。
- 对最终保存并准备交付的 PPT 检查：正确页序、真实图片嵌入、文字换行、遮挡、裁切、高亮和必要的页码更新。保留原有页序调整，避免插图时恢复旧版内容。
- 渲染并查看实际最终文件的修改页；小改动同时检查其余内容没有意外变化。脚本运行成功或中间预览正常都不能替代最终验收。
- 简短交付：提供完整 PPT，说明图或修改位于第几页；仅补充影响使用的限制，不用长篇过程说明代替交付。

**完成标准：只有在最终交付的 PPT 中确认修改存在，才可以说“已完成”。**
