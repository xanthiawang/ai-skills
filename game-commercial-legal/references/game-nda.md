# 游戏 NDA 补充问题

与 `triage-nda` 共同使用；先读同目录 `core-review.md`。这些是针对性问题，不是固定条款或所有法域的法律要求。

- 本次谁披露、谁接收？是 KOL/品牌合作/测试/供应商用途，还是双向评估？单向承诺可以符合特定交易，不自动改成互负义务。
- 项目名、游戏正式名、测试版本、素材、未公开角色、路线图、合作条件、激励和宣传排期是否清晰？避免把过窄的群名称作为唯一信息范围，也不无限扩成所有信息。
- 实际披露渠道有哪些：群、官方服务器、单独频道、私信、邮件、会议、素材平台？退出某个群是否被误写为保密义务结束？不假定私信必然属于服务器内部频道。
- 信息接触范围、允许用途、合作团队/分包方、保密例外和依法披露是否与交易及适用法匹配？不把未公开事实、知识产权归属与保密义务混成一件事。
- 评估/测试访问、公开宣传和商标/素材使用是否另需许可与监修？NDA 不自动授予公开发布、代言或商业化权限。
- 协议期限、每次披露的义务起算、存续期与公开节点是否矛盾？不把通用模板的年限当作普遍法律结论。
- 无偿合作、尚未签主合同、单方承诺场景下，损害赔偿基数、责任上限、救济与可执行性是否需要本法域专项核验？不默认违约金当然有效或当然无效。
- 返回/删除、合理留存、账号权限撤销、泄露响应是否可操作？不要为了技术上不可保证的“彻底删除所有备份”作虚假承诺。
- 原件是否含旧 KOL 的姓名、证件、住址或签署痕迹？给新对象准备模板时只处理明确授权的副本，不转发旧执行件。

输出按需要包括：当前披露模型、可见文本中的缺口、最小改动建议、待业务/数据/当地律师确认项。初筛等级不是签约批准。
